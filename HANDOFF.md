## What Eidolon is

A fork of Stylus Labs [Write](https://github.com/styluslabs/Write) (AGPL-3.0, C++/SDL
handwriting notes app), rebranded to **Eidolon**, package **`ca.helu.eidolon`**, headed for
Google Play **internal testing only**. Renamed to avoid any impersonation of Stylus Labs;
attribution is retained in the About box and the source stays public per AGPL.

Robert added WebDAV sync (static curl + mbedTLS prebuilts, committed under
`syncscribble/android/prebuilt/`, regenerated by `syncscribble/android/build-curl.sh`).
Robert uses the app daily (Android + iOS), and upstream is unmaintained, so this fork is
the maintained lineage now. Expected cadence: one platform-maintenance pass per year around
each Play target-SDK deadline (Aug 31).

## The three bugs fixed this session — CHECK OTHER PLATFORMS

All found at target API 35 on the 16 KB emulator, all measured before fixing (see git log
`80d574f`, and MEMORY: debug-by-measurement). Permanent lifecycle logging now exists in
`Application::processEvents()` (PLATFORM_MOBILE): every SDL app-lifecycle event, window
event, and render-reset event is logged — use it on any platform before theorizing.

1. **Edge-to-edge insets (Android-only by nature).** At target 35+ the window spans the full
   display; the toolbar rendered behind the status bar. Fix: `OnApplyWindowInsetsListener` in
   `MainActivity.onCreate` pads the SDL surface's **parent layout** (SurfaceView ignores its
   own padding). Gated `SDK_INT >= 35`; verified still correct at target 36.

2. **saveSem self-deadlock on pause** (`scribbleapp.cpp` `sdlEventFilter`). SDL 2.0.9 sent
   `SDL_APP_WILLENTERBACKGROUND` from the Android activity thread; the filter handed the save
   to the SDL main thread and waited on `saveSem`. Modern SDL sends it **from the SDL main
   thread itself** → the handoff waited on our own thread → freeze on pause, black screen and
   dead input on re-open. Fix: `Application::mainThreadId` check — save directly when already
   on the main thread. **Cross-platform note:** the handoff path is Android-`#if`'d (iOS and
   desktop call `appSuspending()` directly), but any platform whose SDL changes event-delivery
   threading could grow an equivalent bug. The mainThreadId guard is the pattern to copy.

3. **First swap into a recreated surface never latched** → app redrew correctly but the screen
   stayed black until *later* swaps (proven by injecting taps: more swaps → screen recovered).
   Write presents **dirty rects only**, so after surface recreation nothing forces full-frame
   swaps into every buffer of the swapchain. Fix: `androidExtraSwaps = 2` on
   `SDL_WINDOWEVENT_RESTORED` → extra full blit+swap passes in `layoutAndDrawSW`
   (USE_GL_BLITTER variant, `application.cpp`).
   **→ PRIME iOS SUSPECT.** The iOS app has opened to a black screen (kill-and-restart
   recovers) for over a year. Same fragility class: svggui's RESTORED→full-redraw handling
   (`ugui/svggui.cpp` ~1196) is `PLATFORM_ANDROID`-gated, and the extra-swap fix is
   Android-gated too — **iOS has no resume-redraw path at all**. If iOS discards the
   framebuffer while backgrounded, dirty-rect-only presentation shows stale/black forever.
   *Unconfirmed on iOS* — investigate by building the `xcode/` project for the simulator
   (Makefile's iOS branch works on this Mac since the XPC_FLAGS fix, `b38fb51`),
   backgrounding/foregrounding, and reading the now-permanent lifecycle logs: which events
   arrive on iOS resume, and does anything redraw? iOS presents via `layoutAndDrawGL`
   (`nvglFB`/presentRenderbuffer path), not the SW blitter — the fix will be analogous, not
   identical. Also note the SDL 2.32.10 upgrade has only been exercised on Android; check the
   xcode project still builds against it.
