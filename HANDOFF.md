# Eidolon — session handoff (2026-07-25)

Working notes for continuing on another machine. Not part of the app; delete when stale.

## What Eidolon is

A fork of Stylus Labs [Write](https://github.com/styluslabs/Write) (AGPL-3.0, C++/SDL
handwriting notes app), rebranded to **Eidolon**, package **`ca.helu.eidolon`**, headed for
Google Play **internal testing only**. Renamed to avoid any impersonation of Stylus Labs;
attribution is retained in the About box and the source stays public per AGPL.

Robert added WebDAV sync (static curl + mbedTLS prebuilts, committed under
`syncscribble/android/prebuilt/`, regenerated by `syncscribble/android/build-curl.sh`).

```sh
cd ~/git/eidolon && git fetch ~/gh/Write master && git merge --ff-only FETCH_HEAD && git push origin master
```

`heluca/ulib`, rest upstream. Clone with `--recurse-submodules`.

Both remotes are at `e7296ff` as of this handoff.

## Toolchain

- **NDK r27.0.12077973** everywhere — app `ndkVersion`, the CI image's baked NDK, and the
  toolchain the committed curl/mbedTLS prebuilts were built with. Don't mix versions.
- r27 needs exactly one SDL patch: `ALooper_pollAll` → `ALooper_pollOnce` in
  `src/sensor/android/SDL_androidsensor.c:165` (r27 removed the API; this is upstream SDL's
  own fix). Already on `heluca/SDL@8e7ab8a13`, which is both the branch tip and the pinned
  submodule commit.
- JDK 21, AGP 8.4, Gradle 8.6, compileSdk 36, build-tools 36.0.0.
- The `SDL` submodule **must be on branch `write-android`** — `syncscribble/Makefile` hard-gates
  on the branch name, so a detached HEAD fails. CI does `git switch -C write-android` (creates
  the name at the *pinned* commit rather than chasing the remote tip).

Local build (Linux box):

```sh
cd syncscribble/android
ANDROID_HOME=$HOME/Android/Sdk ./gradlew --no-daemon assembleRelease bundleRelease
```

`ANDROID_HOME` is required (no `local.properties` in the repo). `./gww` is the upstream
bootstrap wrapper; `./gww --install-sdk` installs the SDK/NDK if starting fresh.
Full 3-ABI build from cold is ~6-7 min.

## CI

`.gitea/workflows/build-apk.yml` on Gitea. Runs in container `git.helu.ca/r/android:2026.07`
(immutable tag; **never `:latest` for real builds**). One Gradle invocation produces both:

- artifact `eidolon-release-aab` → **for Play Console** (new apps must upload a bundle)
- artifact `eidolon-release-apk` → **signed**, for `adb install -r` on test devices

Both signed with the publisher-wide `heluca-upload` key, injected at build time via
`-Pandroid.injected.signing.*` (Heluca convention — there is deliberately **no** `signingConfig`
in `build.gradle`). Secrets: `UPLOAD_KEYSTORE_BASE64`, `UPLOAD_KEYSTORE_PASSWORD`,
`UPLOAD_KEY_PASSWORD`, plus `PACKAGE_TOKEN` to pull the image.

The toolchain image is built by `r/android`'s own `builder-image.yml`: **push a git tag**
(e.g. `2026.08`) on `r/android` and CI builds + pushes that image tag using `PACKAGE_TOKEN`.
Don't `docker push` by hand; this host has no registry credentials.

Run history: #1 failed (gradlew wasn't committed — fixed by vendoring it), #2/#3/#5 green,
#6 in progress at handoff time (the 16 KB fix). Check status with the Gitea MCP tools
(`list_repo_action_runs`, `get_repo_action_job_log_preview`, owner `r`, repo `eidolon`) or at
https://git.helu.ca/r/eidolon/actions

## Recent work (newest first)

- `e7296ff` **16 KB page alignment**. Play requires it at target 35+; Android 15+ devices can
  boot with 16 KB pages and can't load 4 KB-aligned `.so`s. Added
  `APP_LDFLAGS := -Wl,-z,max-page-size=16384` to `syncscribble/android/app/src/main/jni/Application.mk`.
  Verified `libmain.so`/`libSDL2.so`/`libc++_shared.so` are `0x4000` on arm64-v8a and x86_64
  (armeabi-v7a's `libc++_shared.so` stays `0x1000` — NDK prebuilt, and 16 KB is 64-bit-only, so
  it doesn't matter). NDK r28 would default to this.
- `6cbf21f` **target API 35 + scoped storage**. All storage now under
  `/sdcard/Android/data/ca.helu.eidolon/files/` via `SDL_AndroidGetExternalStoragePath()`.
  Removed the legacy `/sdcard/helu/*` paths, the whole permission flow (`hasAndroidPermission()`
  / `requestAndroidPermission()` are now stubs returning false), the `STORAGE_PERMISSION` event
  handler, `MANAGE_EXTERNAL_STORAGE` + `WRITE_EXTERNAL_STORAGE` + `requestLegacyExternalStorage`
  from the manifest. Added `android:exported="true"` (required at 31+). FileProvider switched to
  `external-files-path`. compileSdk 30 → 36.
- `43a13c8` pin CI to `r/android:2026.07`; `fbcb2fb` emit `.aab` + `.apk`;
  `f8d8065` vendor the gradle wrapper; `ed82619` converge on NDK r27.

**Storage decision (Robert's call):** the device copy is effectively a cache — uninstall deletes
it — and WebDAV sync is the durable copy. The alternative (Storage Access Framework, for
user-visible files) is a large refactor of a POSIX-path C++ codebase; `MANAGE_EXTERNAL_STORAGE`
would need Play approval that wouldn't be granted.

## → START HERE: the open bug

**On an Android emulator, the app launches and drawing works, but the toolbar is missing and
controls don't work right.** Untested on physical hardware. This has never been debugged — no
device was attached to the Linux box (`adb devices` empty), which is the main reason for moving
to the Mac.

SDL, GL, and the native renderer are all fine (drawing proves it). It's the UI layer. Two
suspects, in order:

1. **UI resources not found.** Toolbar icons are SVGs loaded via `SvgGui::useFile(...)`, and
   fonts are unpacked to `savedPath` on first run (`scribbleapp.cpp:101-113`,
   `AndroidHelper::rawResourceToFile`). `savedPath` moved in `6cbf21f`. If the unpack failed or
   something still points at an old path, you get exactly this: a working canvas, a dead UI.
   **This is the suspect I'd check first — it's what changed.**
2. **API 35 edge-to-edge.** At target 35 the system stops insetting the window, so SDL sees the
   full screen including under the status/nav bars. Controls would render but be displaced or
   mis-hit — fits "controls don't work right" better than it fits a missing toolbar.

First commands to run on the Mac:

```sh
adb logcat -c && adb shell am start -n ca.helu.eidolon/.MainActivity && sleep 5 \
  && adb logcat -d | grep -iE "eidolon|SDL|scribble|write|Error|Exception"

adb shell run-as ca.helu.eidolon ls -la /sdcard/Android/data/ca.helu.eidolon/files/.saved/
adb shell run-as ca.helu.eidolon ls -laR /sdcard/Android/data/ca.helu.eidolon/files/ | head -50
```

A good bisect if it's ambiguous: build at `43a13c8` (pre-scoped-storage, target 29) and see
whether the toolbar is fine there. That cleanly separates suspect 1 from suspect 2.

Note the Mac needs its own Android SDK + NDK r27.0.12077973 to build locally — or skip local
builds entirely and pull the signed APK artifact from Gitea CI, which is self-contained.
